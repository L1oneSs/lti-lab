# Запуск лабораторной в GitHub Codespaces

В репозитории должны лежать файлы этой папки в корне, включая `.devcontainer`. Node.js 24 и Docker настраиваются контейнером разработки. MongoDB запускается через исходный compose.yaml. 

Краткая инструкция по запуску:

Открыть Codespace https://upgraded-space-capybara-rvwqqv75vxr35r94.github.dev/

1. Выполнить команду

```bash
cd /workspaces/lti-lab
docker compose up -d mongo
npm start
```

2. Порт 3000 сделать публичным

3. Проверить состояние сервера 

https://upgraded-space-capybara-rvwqqv75vxr35r94-3000.app.github.dev/healthz

Ожидается вывод:

```json
{"ok":true,"configured":true}
```


Полная инструкция:

1. На странице репозитория: Code → Codespaces → Create codespace on main (или на ветке, содержащей этот проект).
2. Дождаться выполнения команд создания окружения: `npm ci` и создания локального `.env`. При старте Codespace запускается `docker compose up -d mongo`.
3. В терминале проверить `node --version` и `docker compose ps`. Если MongoDB не запущена, выполнить `docker compose up -d mongo`.
4. Заполнить в `.env` точные адреса Moodle. Client ID и Deployment ID до создания регистрации остаются пустыми. PUBLIC_URL уже вычислен из имени Codespace.
5. Выполнить `npm test`, затем `npm start`. Оставить процесс работающим.
6. Открыть вкладку Ports, найти порт 3000 и установить Port Visibility → Public. Порт 27017 не публиковать. Node.js обслуживает HTTP внутри Codespace, внешний адрес порта использует HTTPS.
7. Скопировать Forwarded Address порта 3000 и проверить, что он совпадает с PUBLIC_URL. Открыть `<адрес>/healthz`: ожидается `{"ok":true,"configured":false}` до регистрации.
8. Проверить доступ без авторизации GitHub, например в приватном окне. Промежуточная страница или требование входа не считается ответом приложения. Для AGS и LTI необходима доступность серверу Moodle.
9. Создать новую регистрацию LTI 1.3, используя этот адрес для `/lti/launch`, `/lti/login`, redirect `/lti/launch` и `/lti/keys`. Для формы только с PEM следовать ветке PDF для Moodle 3.7.
10. Перенести реквизиты регистрации Moodle в `.env`, перезапустить Node.js и выполнить сценарии А/Б из LAB-STATUS.md.

Старые Cloudflare-адреса в документах локального запуска не использовать для Codespaces. Данные MongoDB и папка data относятся к конкретному окружению; перед пересозданием/удалением Codespace сохранить необходимые данные. Не удалять том MongoDB при обычной остановке: в нём ключи регистрации.

Codespaces — среда демонстрации, которая должна оставаться работающей во время проверки. При остановке процесс приложения перестаёт обслуживать запросы. После старта снова выполнить `npm start`; остановка Node.js также требует нового запуска элемента из Moodle для создания сессии.

`.env`, журналы, node_modules, локальный npm-кэш, данные попыток и ключи исключены из Git через `.gitignore`. Не загружать их вручную.

Конфигурация подготовлена локально; запуск в реальном Codespace и доступность публичного порта проверяются после загрузки в репозиторий.
