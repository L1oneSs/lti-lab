# Лабораторная: основы HTML через Moodle LTI

Состояние на 11.10.2026: код подготовлен, автоматические тесты пройдены. Размещение и проверка настоящего Moodle ещё не выполнены.

## Собственные задания

| ID | Вопрос | Ответ | Баллы |
|---|---|---|---|
| q1 | Какой HTML-тег создаёт гиперссылку при наличии атрибута href? | a | 3 |
| q2 | Какой HTML-тег вставляет изображение через атрибут src? | img | 3 |
| q3 | Какой HTML-тег обозначает нумерованный список? | ol | 4 |

Вводится имя тега без скобок и атрибутов. Сервер удаляет пробелы по краям и игнорирует регистр. Пустой или неверный ответ даёт 0 за вопрос. Например, ` IMG ` принимается, а `<img>` не принимается. В журнал передаётся последняя завершённая попытка; повтор доставки оценки сохраняет ту же попытку.

Правильные ответы находятся в `src/grading.mjs`, форма получает публичные поля заданий через API. Добавлены пояснения формата ввода, максимального балла и правила последней попытки; сохранены подписи полей и область `role="status"`.

Среда: Windows, Node.js 24.21.0 (отдельная версия в локальном npm-кэше), зависимости из исходного `package-lock.json`.

Результат: **7 tests, 7 pass, 0 fail**.

- Три исходных теста: нормализация/нулевой результат, максимальный/частичный результат, некорректный ввод.
- Три дополнительных: регистр и пробелы для HTML, запрет скобок и атрибутов, различение `ol` и `ul`.
- Интеграционный тест исходного каркаса: подписанный LTI-запуск, имитация OAuth/AGS, идентичность А/Б, запрет Instructor, подмена userId, неправильный CSRF, replay nonce, повтор запроса и восстановление после сбоя AGS.

Сообщение `AGS не подтвердил оценку: HttpError` в этом тесте ожидаемо: это специально вызванный сбой имитированного сервиса. Тест не требует MongoDB и настоящего Moodle. Проверка в браузере на действующем стенде ещё не проводилась.

## Повторный запуск тестов на этом компьютере

Из каталога проекта в PowerShell:

```powershell
npm.cmd exec --offline --cache .npm-cache --package=node@24 -- node --test test/grading.test.mjs test/integration.test.mjs
```

Команда использует уже скачанный Node.js 24. На другом компьютере с установленным Node.js 24+ достаточно `npm.cmd ci`, затем `npm.cmd test` (в Linux — `npm ci`, `npm test`). Системный Node.js на текущем компьютере остаётся версии 22.17.0.

## Что требуется для следующего этапа

Сейчас получен только архив. Для работы настоящего приложения нужны постоянно доступный HTTPS-адрес, Node.js 24+, MongoDB и возможность запускать/обновлять процесс. Необходимо согласовать стенд до заполнения адресов в `.env`.

Вопрос преподавателю:

> Каркас получен, свои задания подготовлены, 7 автоматических тестов проходят. Где нужно размещать приложение: есть ли учебный сервер с Node.js 24, MongoDB и HTTPS-доменом и как загрузить туда код? Можно ли создать отдельную регистрацию LTI 1.3 для моей работы, и кто выдаст две тестовые учётные записи студентов?

Ранее в Moodle были видны `moom` и `ltidemo`, но редактирование `ltidemo` запрещено текущей роли. Не используйте реквизиты чужой регистрации для нового приложения без согласования. Наличие формы создания инструмента ещё не доказывает возможность завершить регистрацию.

После определения стенда:

1. Создать `.env` из `.env.example` и указать настоящие адреса; сначала оставить Client ID и Deployment ID пустыми.
2. Запустить MongoDB и Node.js за HTTPS-прокси, проверить `/healthz`.
3. Зарегистрировать LTI 1.3: `/lti/launch`, `/lti/login`, `/lti/keys`; для формы с PEM использовать `/tool-public-key` по инструкции PDF.
4. Перенести точные реквизиты Moodle в `.env` и перезапустить процесс. Не угадывать issuer и подкаталог Moodle по названию сайта.
5. Разрешить AGS и приём оценок, создать элемент с максимумом 10 и запуском в новом окне.
6. Выполнить реальные сценарии и сохранить скриншоты.

## Реальные проверки — заполнить после размещения

| Сценарий | Ожидается | Фактически |
|---|---|---|
| Студент А: x / x / x | 0/10 и 0 в журнале | Не проверено |
| А: новая попытка a / x / ol | 7/10 вместо 0 | Не проверено |
| А: новая попытка a / img / ol | 10/10 вместо 7 | Не проверено |
| Повтор отправки | Та же попытка, без новой колонки | Не проверено |
| Студент Б: x / x / x | У Б 0; у А остаётся 10; история А скрыта | Не проверено |
| Преподаватель | Просмотр без отправки оценки | Не проверено |

Для сдачи исключить `.npm-cache`, `node_modules`, `.env`, `data` и ключи из архива. Этот документ содержит результаты локальных тестов, а не подтверждение интеграции с реальным Moodle.
