# Протокол проверки настоящего Moodle

Дата и время: заполнить. Проверяющий: заполнить. Учётные записи А/Б: указать обезличенные обозначения. Название элемента: `LTI — Тест` (сверить с фактическим).

«Не проверено» означает отсутствие доказательства. Ожидаемые баллы нельзя переносить в столбец фактических без выполнения сценария и проверки журнала. Для А/Б нужны две отдельные учётные записи студентов, зачисленные на курс.

## Положительные сценарии

| Сценарий | Ожидается в тренажёре | Ожидается в журнале | Фактически | Доказательство |
|---|---|---|---|---|
| А: x / x / x | 0/10, отправка подтверждена | У А 0 | Не проверено | — |
| Новая попытка А: a / x / ol | 7/10 | У А 7 вместо 0 | Не проверено | — |
| Новая попытка А: a / img / ol | 10/10 | У А 10 вместо 7 | Не проверено | — |
| Обновить окно / повторить текущий запрос | Та же попытка | Та же колонка и балл | Не проверено | — |
| Б: x / x / x | 0/10, история А не видна | У Б 0, у А остаётся 10 | Не проверено | — |
| Преподаватель | Просмотр, поля отключены | Преподавателю оценка не отправляется | Экран просмотра подтверждён; журнал и прямой POST не проверены | Скриншот в чате, файл ещё не добавлен |

## Отрицательные проверки

| Запрос | Ожидается | Фактически | Доказательство |
|---|---|---|---|
| GET /api/session без сессии | 401 | Не проверено на Codespaces | — |
| POST преподавателя | 403 | Не проверено на настоящем стенде | — |
| POST студента без CSRF | 403 | Не проверено на настоящем стенде | — |
| Дополнительное поле userId | 400 | Не проверено на настоящем стенде | — |
| Дополнительное поле scoreGiven | 400 | Не проверено на настоящем стенде | — |

Проверка без сессии из отдельного терминала:

```bash
curl -i https://upgraded-space-capybara-rvwqqv75vxr35r94-3000.app.github.dev/api/session
```

Для остальных проверок открыть DevTools → Console именно в окне тренажёра, запущенного из Moodle. Код ниже использует неверные ответы и при корректной реализации не создаёт оценку. Под студентом проверяются CSRF и лишние поля; под преподавателем — серверный запрет POST. Перед запуском убедиться, что в каждой строке передан указанный ожидаемый статус.

```javascript
const session = await fetch('/api/session').then(r => r.json());
async function probe(label, extra, csrf, expected) {
  const headers = { 'Content-Type': 'application/json' };
  if (csrf) headers['X-CSRF-Token'] = csrf;
  const response = await fetch('/api/submit', {
    method: 'POST', headers,
    body: JSON.stringify({
      requestId: crypto.randomUUID(),
      answers: { q1: 'x', q2: 'x', q3: 'x' }, ...extra
    })
  });
  console.log(label, 'ожидалось', expected, 'получено', response.status);
}
if (session.learner) {
  await probe('Без CSRF', {}, null, 403);
  await probe('Подмена пользователя', { userId: 'other-user' }, session.csrf, 400);
  await probe('Подмена балла', { scoreGiven: 10 }, session.csrf, 400);
} else {
  await probe('POST преподавателя', {}, session.csrf, 403);
}
```

После проверок убедиться, что оценки в журнале не изменились. Не публиковать session, csrf, cookie, ltik или id_token; на снимке консоли достаточно подписей и HTTP-статусов.
